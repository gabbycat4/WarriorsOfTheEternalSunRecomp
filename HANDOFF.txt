Done
- Phase 0-1: game plays cleanly (1087 native routines, engine fixes pushed to
  the gabbycat4 forks, wotes branches).
- Phase 2: motion measured. World map: camera 1 px/frame. Battles: 8 px hops
  every 9 frames.
- Phase 3: 240 Hz pacing works (Esc -> Mods -> High refresh rate).
- Phase 4.2: in-between pictures with motion. Battles are much smoother.
- Phase 4.3 tested (Step 26, measurements/quarter-1.*): 4x pictures are
  pixel-exact, but drawing took avg 2-4 ms, max 10.6 ms while walking
  (budget 4.17 ms at 240) -> 1,495 late pictures, 3.2 instead of 4 pictures
  per frame = the stutters and the 180-240 FPS. Mountain shadows = 1-px
  checker dither in the map tiles (not sprite flicker: reg12 = $81, sprite
  counts steady), shimmering as it scrolls.
- Phase 4.4 tested (Step 27, measurements/cache-1.*): dither blending
  WORKS (user: mountains no longer flicker). Speed did not improve: cache
  reused only ~50% while walking (grouping changes every picture), first
  picture of each frame still draws everything; 3.68 pictures/frame,
  2,915 late, 78 badly late. User: still 160-240 FPS.
- Phase 4.5 WORKS (Step 28, gpu-1.*: 4.00 pictures/frame, late gaps 2,915 -> 157,
  user sees 238-240 FPS, no flicker): GPU layers, the DuckTales
  method (DuckTales_lessons.txt lesson 9). Each frame is built ONCE as
  layers (planes low/high scrolled with a 32 px margin, side panel fixed,
  sprites in groups that move together, low/high), the graphics card places
  them at fractional positions. Engine: GameVideo.presentation_layers +
  present_layers() in runner/main.c (GENESIS_GPU_LAYERS=0 = off). Game:
  wotes_presentation_layers() in game/wotes_video.c (WOTES_VIDEO_GPU=0 = off,
  falls back to the 4.4 CPU path). Backups: measurements/before-4.5/.

- Phase 4.5b confirmed in a battle too (gpu-2.*: check 0/126 failed).
